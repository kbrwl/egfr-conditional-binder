# EGFR conditional binder — working record

De novo design of pH-conditional miniprotein binders against the extracellular region
of human EGFR, the epidermal growth factor receptor. Entry for Challenge 1 of the
Anthropic × Adaptyv Protein Design Competition, Track 3 (open track), October 2026.

The design objective, in the organisers' order of importance:

1. **pH selectivity** — bind human EGFR at pH 6.5, with no detectable binding at pH 7.4
2. **Mouse cross-reactivity** — the same sequence must also bind mouse EGFR
3. **Human binding** — bind human EGFR at all, with affinity as the measure

This repository is the complete working record: the analysis that chose the target
surface, the design pipeline, every screen applied to the candidates, every attempt
that produced nothing, and every claim the project made and then disproved.

**The submission itself is in `submission/`.** Start there if that is what you came for:
`submission/methods.md` is the written method, `submission/challenge1-egfr-submission.csv`
is the ranked set of designs.

## Directory map

```
analysis/              numbered standalone scripts, run in order, plus egfr_common.py
                       for anything two of them both need. Each writes prose findings
                       to results/findings/ and tables to data/derived/.
data/sequences/        input sequences (tracked)
data/structures/       downloaded structures (not tracked; analysis/02 re-downloads them)
data/derived/          computed tables, CSV (tracked, small)
results/findings/      computed findings in markdown (tracked)
results/candidates/    bulk design output (not tracked, except the final shortlist)
design/configs/        campaign files for the design run, generated by analysis/09
design/modal/          the GPU runner and its instrumentation
submission/            the submission CSV and the written method
explorer/              interactive viewers for the structural findings
docs/                  decisions, rules, glossary, explainers
```

**Nothing under `results/` or `data/derived/` is hand-written.** Every file there is the
output of a script in `analysis/` and comes back by rerunning it. If a number there
looks wrong, the script is what needs fixing. Prose in `docs/` may quote those numbers
and every such number is traceable to the script that produced it.

## Reproducing the analysis

```
python analysis/00_numbering_check.py      # run this first, always
python analysis/NN_<name>.py               # then any step, in numeric order
```

`analysis/00` asserts the residue-numbering convention and exits with an error if it
breaks. Run it before anything else; if a later step gives a strange answer, run it
again before believing the answer.

**Residue numbering, because getting it wrong is silent.** Every residue number in this
repository is a position in the full human UniProt record P00533, which is 1210 amino
acids long. Residues 1–24 are the signal peptide and the mature extracellular region
runs 25–645. The competition constructs are that region, so:

    UniProt position = challenge-construct position + 24

Structure files carry their own numbering and nothing in the file records which
convention it follows. Both structures used here are offset by 24. The offset is
measured empirically against known residue identities and the check is printed, never
assumed, because getting it wrong shifts every result by 24 positions and raises no
error.

Most scripts carry a `--self-test` or `--break-rule` switch that disables one of their
own checks on purpose and confirms the matching test then fails. A check that has never
been seen to fail is not known to work, and that is the rule these switches exist for.

## How this work was produced

This repository was built by one person working with AI tooling, and the division of
labour is recorded rather than implied. Commit messages carry AI co-authorship
attribution.

**What the AI tooling did:** wrote the analysis scripts, ran the design pipeline,
produced the findings files, and drafted the documents.

**What was decided by the human owner, and where each decision is recorded:**

- The target epitope and the anchor set. Changing either is listed in `CLAUDE.md` under
  "These come back to Kunal, in chat" as a decision the tooling may not make on its own.
- The pairing rule, the affinity direction, and every rejection criterion, including the
  decision to demote one of them during final selection. See `methods.md` section 9.2.
- Every dollar of GPU spend. No campaign against the real target was started without an
  explicit authorisation, and the authorisations are recorded with their date and their
  ceiling in `docs/decisions-log.md`.
- What goes into the submission, how many designs, and in what order.
- **Commitments made in advance to bind later work.** The decisions log holds a section
  of rules set deliberately before the deadline pressure arrived: a hard rule that the
  pipeline outranks all epitope work past a stated date, a time box on one line of
  investigation, and a standing decision not to read another entrant's public repository
  on the same problem. These were made to stop later sessions relitigating them, and
  they held.
- The standard the work is held to, which is `CLAUDE.md` in full: claims must be
  computed rather than recalled, anything stated from memory is labelled unverified and
  may not be built on, a disproved assumption is recorded as disproved rather than
  quietly dropped, and anything computed twice must be computed once.

The three claims this project withdrew after its own computation disproved them are
listed in `methods.md` section 10. They are kept deliberately. A design record
containing only its successes cannot be checked.

## Licence and reuse

The analysis scripts are written to be reusable against a new target by swapping the
sequences and the epitope rather than by rewriting them, because four further challenges
follow this one. Single-use code is treated as a defect here.

BindCraft2, used to generate the binder backbones and sequences, is under a
source-available licence of its own; see its repository for terms.
